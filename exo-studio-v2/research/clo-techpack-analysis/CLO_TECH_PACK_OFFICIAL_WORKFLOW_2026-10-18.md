# CLO 3D / CLO-SET Tech Pack: official workflow, data model, exports and ClothCraft implementation research

**Research date:** 18 October 2026 (US Eastern). **Scope:** What garment developers actually author inside CLO 3D; the official hand-off to CLO-SET; how the generated Web, 3D and Excel/PDF Tech Packs work; what can be exported directly; and a grounded requirements map for EXO ClothCraft. This is a read-only analysis; no production code, garment files or live CLO settings were changed.

**Primary conclusion:** CLO 3D is the *source authoring* environment for patterns, physical/visual garment construction, BOM-relevant scene objects, size grading and POM. CLO-SET is the *live production-document, review and export* environment. CLO itself also supports structured BOM XML, Tech Pack JSON through its developer API and technical drawing/schematic capture; these are not identical to a polished editable PDF or Excel factory Tech Pack. The 2026 CLO-SET Content Page transition materially changed some historical UI instructions.

## A. Evidence hierarchy and important current-version correction

- **Official desktop guidance:** [CLO: `[CLOSET] Techpack`](https://support.clo3d.com/hc/en-us/articles/360013304233--CLOSET-Techpack), updated September 24, 2026, explicitly places the entry point at **File → Share via CLOSET → Tech Pack via CLOSET**, or the Share via CLOSET menu. It redirects to CLO-SET; the page does not describe an all-in-one editable production Tech Pack builder entirely inside the desktop 3D viewport.
- **Current CLO-SET information:** [CLO-SET Web Tech Pack](https://support.clo-set.com/hc/en-us/articles/45303168383385-Web-Tech-Pack-WTP), [Intro](https://support.clo-set.com/hc/en-us/articles/45303157973657-Intro-Web-Tech-Pack), [Excel export](https://support.clo-set.com/hc/en-us/articles/45303206577817-How-To-Excel-Tech-Pack), [BOM](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM), [Measurement](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement), [Construction](https://support.clo-set.com/hc/en-us/articles/45303219780377-Web-Tech-Pack-Construction).
- **2026 transition:** [Official October 2026 legacy retirement notice](https://support.clo-set.com/hc/en-us/articles/62030947837593--Important-Notice-End-of-Support-for-the-Legacy-Content-Page) says the New Content Page replaced the legacy page on **October 13, 2026 (October 15 Enterprise)**. Legacy deep links now open the new page. The Construction tab in the new Content Page initially opens the familiar Construction view; **3D Tech Pack** is reached through the **Viewer**. A newly integrated Construction/Tech Pack Designer UI is described as a future year-end release; do not label it as released today. Many older Help Center articles still describe clicking a *legacy* Web Tech Pack icon: their behavioral descriptions remain informative but their navigation needs the 2026 correction.
- **Where confidence is lower:** historical CLO app menu locations for Tech Pack JSON may vary by version. The developer API explicitly names `ExportTechPack`, whereas screenshots in CLO-SET's Virtual Showroom guide show **File → Export → Tech Pack (JSON)** as an application export menu. Confirm in the user's installed native CLO build before presenting the desktop menu as a guaranteed label. Exported JSON is structured data plus images, and cannot be treated as a factory-facing workbook merely because it is called a Tech Pack.

## B. End-to-end: how to make a Tech Pack using CLO today

1. **Prepare the design in CLO 3D.** Open/create the style; finish its pattern pieces, sewing, trims, fabrics, graphics, colorways and grade sizes. Choose clear names and item numbers for fabrics, buttons, graphics and relevant objects in the Object Browser/Property Editor. CLO-SET reads native style data. A beautiful rendered garment alone does not supply factory tolerances, fiber composition, supplier part numbers or sewing instructions. [BOM article](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM); [Graphic properties](https://support.clo3d.com/hc/en-us/articles/360049969394-Graphic-Properties); [Button style properties](https://support.clo3d.com/hc/en-us/articles/115000573587--Style-Property-Button).
2. **Create Points of Measure (POMs) for production specs.** Go to **2D Pattern → Pattern Measure → Point of Measure**, or choose the 2D POM tool. Click a pattern outline/internal line to start and double-click the endpoint or press Enter to finish. CLO offers Single and Group POM; grouped linking spans outside pattern boundaries do not contribute length. Hold Shift for orthogonal/45° guides, right-click for exact moved distance, use P to switch line-following versus polygon drawing. A POM appears in **Object Browser → POM**, reports 3D length in Property Editor and graded lengths by size when grading exists. [Create POM](https://support.clo3d.com/hc/en-us/articles/360025716774-Create-POM).
3. **Prepare technical-style pictures.** Activate **Schematic Render** in the 3D window. It produces technical-looking flat views from the garment, with options for silhouette/seam/internal/topstitch line visibility and thickness, line colors, garment color, 2D measurements, text size and brightness. This is useful for front/back technical flats and close-up diagrams, but it is not itself a complete manufacturing instruction sheet with independently verified sewing specifications. Capture views for references and add callouts in the Tech Pack Construction view. [Schematic Render](https://support.clo3d.com/hc/en-us/articles/115000411227-Schematic-Render).
4. **Review whether each object should be included.** For instance, **Graphic Properties** contains a **Techpack (CLO-SET)** checkbox and graphic classification (Embroidery, Logo, Print, Wash). **Button Style Properties** and **Avatar Properties** also offer Tech Pack inclusion controls. This affects what CLO-SET is expected to include; verify actual exported content for the specific file. [Graphic](https://support.clo3d.com/hc/en-us/articles/360049969394-Graphic-Properties), [Button](https://support.clo3d.com/hc/en-us/articles/115000573587--Style-Property-Button), [Avatar](https://support.clo3d.com/hc/en-us/articles/115002227327-Avatar-Properties).
5. **Save a native garment file** (`.zprj` or `.zpac`). This is the important source format for automatically populating CLO-SET Web and Excel Tech Packs. Upload the design to CLO-SET directly, or choose **File → Share via CLOSET → Tech Pack via CLOSET** from CLO; follow the browser redirect and upload instructions. The receiving Content Type should be **Style**, with a `.zprj`/`.zpac` version. [Desktop handoff](https://support.clo3d.com/hc/en-us/articles/360013304233--CLOSET-Techpack); [WTP requirements](https://support.clo-set.com/hc/en-us/articles/45303168383385-Web-Tech-Pack-WTP).
6. **Open the style on the new CLO-SET Content Page.** Check **Overview** for style metadata and versions, **BOM** for fabrics and trims, **POM** for sizes/measurement tables, **Cost Estimation** for expenses, and **Construction** for pattern/material/trim callouts and comments. Open the Viewer for the spatial **3D Tech Pack** widget (pattern/fabric/trim selection). As of October 2026, relying on “switch to legacy Content Page” is outdated. [Retirement notice](https://support.clo-set.com/hc/en-us/articles/62030947837593--Important-Notice-End-of-Support-for-the-Legacy-Content-Page).
7. **Complete the missing factory-specific entries inside CLO-SET.** Edit BOM consumption, unit price, total price and remarks; add fabric/trim rows where needed. In POM, add target values, tolerance and **HTM (How to Measure)** instructions. Use Construction pages to pin annotations, labels, arrows, manufacturing notes, or images. Fill cost estimates such as labor and transportation. These are genuine document-authoring stages and are **not entirely inferred from 3D physics**. [BOM](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM), [Measurement](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement), [Construction](https://support.clo-set.com/hc/en-us/articles/45303219780377-Web-Tech-Pack-Construction), [Intro](https://support.clo-set.com/hc/en-us/articles/45303157973657-Intro-Web-Tech-Pack).
8. **Export for the factory.** In the **new Content Page → Overview → Export (upper right)**, choose the required sections: **Overview, BOM, POM, Cutter's Must, Graphic, Annotation & Comments**. CLO-SET documentation updated June 9, 2026 says export to **Excel or PDF**. The Excel Tech Pack also has a **Download** action under the Overview → Version tab. For a focused sheet, export BOM or POM from its tab; separate Construction pages can be exported as PDF. [2026 export update](https://support.clo-set.com/hc/en-us/articles/58772990176409--2026-06-Updates-in-CLO-SET-Visual-Board-UI-Improvements-Expanded-Tech-Pack-Exports), [How To Excel](https://support.clo-set.com/hc/en-us/articles/45303206577817-How-To-Excel-Tech-Pack), [Construction PDF](https://support.clo-set.com/hc/en-us/articles/45303265919769-Updated-Feature-Web-Tech-Pack-Construction-Export).
9. **Issue an updated version after a change.** Upload a new version of the source project and elect to update Web Tech Pack. Review the changed BOM/POM carefully: some manually created rows persist, deleted items do not always reappear just because they return to the source, and linked trim-file updates are not automatically pulled through. Earlier Tech Pack versions are read-only references, with comments tied to versions. This is version-aware but not a guarantee that every external spreadsheet stays synchronized. [WTP versioning](https://support.clo-set.com/hc/en-us/articles/45303168383385-Web-Tech-Pack-WTP), [BOM update rules](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM), [POM update rules](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement).

### Troubleshooting the initial creation

- **Missing measurements in exported Tech Pack:** create and save POMs inside CLO before uploading; a pattern that happens to have measurable edges does not automatically imply named factory measurement rows. An official CLO community response identifies absent POM authoring as the cause. [Official response](https://support.clo3d.com/hc/en-us/community/posts/360039167034-Tech-pack); [Create POM](https://support.clo3d.com/hc/en-us/articles/360025716774-Create-POM).
- **Tech Pack option not appearing:** check `Style` Content Type, `.zprj`/`.zpac` source and permitted role; the help center says Web Tech Pack requires Style, with Admin/Collaborator/Editor for its management. [WTP requirements](https://support.clo-set.com/hc/en-us/articles/45303168383385-Web-Tech-Pack-WTP). CLO-SET pricing/entitlements should be confirmed against the currently assigned account and plan rather than inferred from old community posts.
- **Measurements appear in incorrect units:** current CLO-SET offers inch/cm/mm display and a **June 2026 POM CSV update** preserves visible columns, column order and selected units. The global company unit setting can warn on upload and tech pack version mismatches. This improves on 2020-era support threads reporting unexpected millimeters. [Current POM](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement), [June 2026 CSV update](https://support.clo-set.com/hc/en-us/articles/59282786628761--2026-06-Updates-in-CLO-SET-Style-Content-Support-for-Non-CLO-Files-Improved-POM-CSV-Exports), [Global units](https://support.clo-set.com/hc/en-us/articles/47494466778905-Global-Unit-Setting-Measurement-Currency).
- **CLO login works but CLO-SET login does not:** historical CLO staff guidance states CLO ID and CLO-SET account credentials were separate. Validate your own current sign-in configuration, rather than assuming a desktop sign-in automatically authenticates CLO-SET. [CLO community note](https://support.clo3d.com/hc/en-us/community/posts/24104167384857-Can-t-login-for-tech-pack-export).

## C. What goes into each section

| Area | CLO-side structured inputs | CLO-SET editable/generated behavior | Manufacturing fields to validate manually |
| --- | --- | --- | --- |
| **Overview** | Native garment/style file, content thumbnail and metadata | Style number, company, brand, line, season, workroom, status, description, custom fields, workflow/schedule, version metadata | SKU, intended factory, owner, approval state, release date, sample stage |
| **BOM — Fabric** | Fabric object names, colors, textures, native references and layout/marker data | BOM auto-filled by colorway/grade/version; edit consumption, unit price, amount, remarks; add rows and external fabric assets | Fabric supplier/ref, composition, width, weight/GSM, finish, shrinkage, dye/color standard, MOQ, ordering basis, bulk approval |
| **BOM — Trims** | 3D button/buttonhole, zipper subcomponents, topstitch/thread, graphics, other trims | Add/delete/edit rows, link eligible CLO-SET assets, associate visually with construction pages | Supplier/part number, color/material/size, pitch/gauge, length/quantity, label details and placement |
| **Construction** | Pattern, fabric, graphic, button head/hole, zipper, topstitch, miscellaneous objects and garment views | Auto markers by object type, 3D viewer, per-type pages, text/arrow/drawing/image annotations, comments/history | Seam class, operation sequence, SPI, stitch type, seam allowances, reinforcement, wash process, finishing, placement tolerances |
| **POM / Measurement** | Defined POM geometry, 2D and possibly mapped 3D values, grading sizes | Group rows, 2D/3D views, select a POM to highlight garment, target specs, tolerance, HTM, manual blank POM rows and grade size columns | Agree measuring method, target per size, upper/lower tolerance, sample actual and corrective action |
| **Cost Estimation** | Fabric/trim items, sizes/colorways and material data | Material costs drawn from BOM; estimated labor, transport, other costs and exchange rates | Supplier quote dates/currencies, cutting waste assumptions, labor operations, duties, packaging, cost validity |
| **Graphic** | CLO graphic style and on-garment placement, type (Logo/Print/Embroidery/Wash), inclusion flag | Optional exported Graphic section; dedicated construction marker page | Screen/embroidery spec, number of colors, artwork scale/placement, Pantone, process and tolerance |
| **Cutter's Must** | Pattern/cutting-source information available in native style file | Explicit section of Excel/PDF Tech Pack export | Piece count, cut quantity, grain, fold, fusing, interlining, notches, cut fabric direction, approved marker/waste and shrinkage |
| **Comments/Versions** | Content revisions | Per-tab comment threads, version history, conditional data refresh, exportable annotations/comments | Approver, release revision, recipients, unresolved change requests and confirmation of the factory's received version |

These categories are derived from official [Excel Tech Pack](https://support.clo-set.com/hc/en-us/articles/45303206577817-How-To-Excel-Tech-Pack), [BOM](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM), [Construction](https://support.clo-set.com/hc/en-us/articles/45303219780377-Web-Tech-Pack-Construction), [POM](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement), [Intro](https://support.clo-set.com/hc/en-us/articles/45303157973657-Intro-Web-Tech-Pack) and [Expanded Exports](https://support.clo-set.com/hc/en-us/articles/58772990176409--2026-06-Updates-in-CLO-SET-Visual-Board-UI-Improvements-Expanded-Tech-Pack-Exports). The **last column is an EXO production design checklist**, not a claim CLO-SET auto-detects supplier specifications or validates factory data.

### Construction page taxonomy, confirmed from official CLO-SET documentation

Historical Construction UI automatically provides pages/markers by entity kind. The numbering conventions documented in the official guide are: Pattern **P1**, Fabric **F1**, Graphic **G1**, Button Head **B1**, Button Hole **H1**, Zipper **Z1**, Topstitch **T1**, and miscellaneous trim **E1**. Pages can include the garment viewpoint and per-material rows; a Pattern page includes the 2D pattern layout. Zipper content may expose **puller, slider, teeth, top stopper and bottom stopper** separately. The annotation toolbar documents image, text, pen, straight/curved line, single arrow, circle, square, color and thickness. Pages can be reordered/duplicated, and a blank page permits entirely manual annotations. See [Web Tech Pack → Construction](https://support.clo-set.com/hc/en-us/articles/45303219780377-Web-Tech-Pack-Construction). The page's old UI navigation is superseded by the October 2026 transition; do not replicate a retired entry point.

### BOM source/override behavior, confirmed

CLO-SET distinguishes source-derived **Name, Color, Texture, Marker** fields from Web-Tech-Pack-edited **Consumption, Unit Price, Total Price and Remarks**. Each colorway/grade/version combination is distinct (for styles uploaded since Nov 5, 2024); additional rows can be blank text rows or linked CLO-SET asset rows. Linked trims do *not* automatically reflect subsequent trim-file version changes. When a new garment file is uploaded, the user explicitly chooses to update WTP data. Existing rows may persist, previously removed materials may stay excluded, and old WTP versions cannot be edited. This calls for a **three-layer state model** in EXO: imported garment facts, manually authored production overrides, immutable published revision. [BOM documentation](https://support.clo-set.com/hc/en-us/articles/45303192584601-Web-Tech-Pack-BOM); [WTP versioning](https://support.clo-set.com/hc/en-us/articles/45303168383385-Web-Tech-Pack-WTP).

### POM 2D, 3D and Target values are separate

A named point-of-measure is constructed in the actual 2D patterns and can provide 2D/3D measurements (CLO-SET says 3D POM is auto-generated when the 2D POM is created). CLO-SET manages **Target**, **Tolerance** and **How-To-Measure** explanatory notes on top. Its viewer highlights the selected POM on the garment; grade sizes live in table columns. For a style without POM data, CLO-SET supports manually creating the measurement table and assigning base and additional sizes. **Do not equate a simulated draped garment dimension with an approved production target**: all three values should be shown with their provenance. [CLO Create POM](https://support.clo3d.com/hc/en-us/articles/360025716774-Create-POM); [CLO-SET Measurement](https://support.clo-set.com/hc/en-us/articles/45303219189785-Web-Tech-Pack-Measurement).

### Official API details worth imitating, without assuming open access

The published developer API defines `ExportTechPack(_filePath, _exportOption)` and `ExportTechPackToStream(...)`; output is **JSON plus related images**. `ExportTechpackOption` includes choices for saving `.zpac`/`.zprj`, scene thumbnails with or without avatar, item thumbnails, high-resolution front capture, 2D pattern layout, fabric/trim marker overlays, turntable, textures and colorways. `ExportTechPackType` enumerates `CLO_TECH_PACK`, `CLO_SET_TECH_PACK`, `CLO_SET_SREST`, `CLO_API_TECH_PACK` and `CLO_DUMMY`. These are API surface descriptions, not proof that every retail user has API access, all output fields have a stable public JSON schema, or the data can be round-tripped into a new CLO project. [API List](https://developer.clo3d.com/list.html); [API Option & Type](https://developer.clo3d.com/optiontype.html).

## E. 3D Tech Pack (different from an Excel/PDF document)

The CLO-SET **3D Tech Pack** widget is a spatial inspection mode in the 3D Viewer. It allows selection of **Pattern, Fabric, Trim** categories and shows material placement/layout on the garment. A [2025 annotation update](https://support.clo-set.com/hc/en-us/articles/45303128139673--2025-04-Updates-in-CLO-SET-Annotation-work-with-3D-Tech-Pack) describes selecting one or multiple pattern/fabric/trim objects, then creating a 3D annotation. This is valuable for checking, for example, which fabric is assigned to which hood panel, zipper/puller locations and details difficult to convey with a flat. [3D Tech Pack](https://support.clo-set.com/hc/en-us/articles/45303161788057-3D-Tech-pack). After the October 2026 migration, access the **Viewer** in the new Content Page ([migration](https://support.clo-set.com/hc/en-us/articles/62030947837593--Important-Notice-End-of-Support-for-the-Legacy-Content-Page)).

This informs a critical EXO product distinction: **Tech Pack interactive mode** (inspect 3D source, highlight actual garment objects, contextual comments) and **Tech Pack document mode** (print pages, size charts, construction operation tables, BOM, export) are two views of the same structured source, and must remain semantically synchronized.

## F. Current EXO ClothCraft baseline (source-inspected, not an end-to-end runtime claim)

**Inspected 2026-10-18:** `src/App.jsx`, `src/core/measurements.js`, `src/core/bomXml.js`, `src/core/factoryPackage.js`, `native_cpp/core/factory_package_files.cpp`, and existing planning doc `docs/EXO_INTERACTIVE_WEB_TECHPACK_PLANNING_2026-10-16.md`. No files were modified for this audit.

### Implemented and source-visible

1. `src/App.jsx` currently wires **Export BOM XML**, **Export POM CSV**, **Export Tech Pack JSON** and **Export Factory Package ZIP** buttons. These are actual export action functions; browser/native deployment fidelity is a separate validation question.
2. `src/core/measurements.js` computes a graded size run and exports a structured proprietary-to-EXO JSON object (`format: garment-studio-tech-pack`, `version: 1`) with source project identifiers, avatar, grading, size measurements, fabric physical parameters/textures, pattern/piece attributes, notches, buttonholes, internal lines, custom measurement endpoints, sewing construction and markers. This is useful semantic data but **is not the CLO API JSON schema**.
3. `src/core/bomXml.js` deliberately creates **open Garment Studio BOM XML**, not proprietary CLO BOM XML; it includes fabric/cut amounts and trim sections. No automatic guarantee of CLO XML import interoperability exists.
4. `src/core/factoryPackage.js` assembles Tech Pack JSON, factory-spec HTML, POM CSV, materials BOM CSV, fabric-costing CSV, BOM XML, structural preflight JSON, piece and seam CSVs, trim-hardware JSON, marker data, DXFs and source JSON. Native mirror: `native_cpp/core/factory_package_files.cpp` includes printable HTML and export file manifest. These form a strong offline starting point.
5. Existing `docs/EXO_INTERACTIVE_WEB_TECHPACK_PLANNING_2026-10-16.md` already describes a future **versioned interactive designer/factory portal** (anchored comments, roles, immutable release snapshots and review). It explicitly treats this as a future concept, not a deployed complete system.

### Missing or not established from this source audit

- There is no verified production-ready **WYSIWYG Tech Pack document editor** integrated with 2D/3D cloth selection and page layout in the audited files. The File Library's Tech Pack category is asset organization, not evidence of such an editor.
- Source inspection does not establish a live multi-author Tech Pack collaboration service, final review/approval/release semantics, factory acknowledgment, version-scoped access to suppliers or actual latest-production PDF/Excel export UI.
- Existing POM logic uses some default geometry-derived templates and custom two-endpoint Euclidean measurements. That is **not** automatically equivalent to CLO's bound, editable single/group POM, 2D/3D physical measurement modes or manually defined factory target/tolerance tables; preserve provenance and warn when 3D measurement was not independently determined.
- Factory costs already include fabric estimates, but cannot be described as complete landed costs unless trim, operations, labor, packaging, freight, tariffs and supplier quotes are added and validated.
- The present JSON schema contains rich construction objects but does not prove complete garment-specific operation sequences, tech-flat callout authoring, label/care instructions, packaging specs, color standards, supplier SKU data or per-sample actual measurements.
- CLO desktop JSON/BOM export interchange should be treated as a **separate integration project** requiring source examples, license/format permissions and real round-trip tests. Do not rename EXO's schema to imply compatibility.

### Proposed EXO implementation contract

**Data ownership:** existing Garment Studio project → extracted base TechPack snapshot → editable factory-level production overlays (by SKU/colorway/grade) → approval/released immutable package. Preserve origin, source hash/revision, unit, author, change time, and foreign-key ID for each POM, pattern edge, stitch, fabric, trim or annotation. Do not overwrite original garment data when a factory reviewer types a proposed measurement.

**UI architecture:** add a Tech Pack workspace under Production/File Library, with **Overview**, **Technical Flats**, **Patterns/Cutter's Must**, **Measurements & Grading**, **BOM/Fabrics/Trims**, **Construction**, **Graphics/Labels**, **Costs**, **Samples/Quality**, **Comments**, **Versions & Release**. Use center stage for schematic/2D/3D selection, a compact left page/section navigator and a contextual right panel for selected anchor or row. Editable rows should show values cleanly with click-to-edit fields, matching current ClothCraft styling constraints.

**Interaction bindings:** selecting an annotated BOM fabric highlights all relevant 2D panels and 3D surfaces; selecting a 3D zipper brings up its BOM row and construction notes; selecting a POM row traces the 2D measurement and, only where measured, the actual 3D path; selecting a sewing pair brings up sewing orientation, seam allowance and operation. Attach comment to semantic IDs so it survives viewport zoom and makes relinking explicit after geometry topology changes.

**Source audit preflight:** require title/style ID; saved project revision; named colorway and size/grade range; material assignments; POM target table and tolerances; sewing/construction instructions; marker/cutter details; graphic placement; required hardware; required production notes. Missing fields should appear as **Needs specification** instead of guessed values. Publishing must create an immutable release, distinct from working draft. Export artifacts stamped with exact revision.

**Outputs:** interactive read-only factory share; PDF with dynamic page breaks and embedded vector diagrams; editable XLSX for BOM and spec sheets; CSV POM; JSON with schema version; offline factory ZIP containing DXF/grading, 2D technical diagram, fabrics/trims, construction and release manifest. Redact internal quotes/costs by role. If no actual generated PDF/XLSX implementation exists, label the planned action instead of advertising it as functional.

## G. Concrete test garment / QA matrix

Use a hoodie with front, back, sleeves, hood, cuff and waistband panels, contrasting colorways, print/embroidery, a zipper variant, plus lining/label where applicable. This exercises both trivial and realistic factory data.

## H. Sequencing recommendation for ClothCraft (research conclusion)

**Milestone 1: Desktop Tech Pack Editor.** Build a single high-fidelity page and schema for garment metadata, POM and BOM with editable rows, linked 2D/3D highlights, a technical-flat generator and an HTML/PDF preview. Base it on existing `buildTechPack`, `measurementRunToCSV`, `factoryPackage` and source garment IDs; use real values and confidence/provenance labels.

**Milestone 2: Production details and multiple variants.** Implement fabric/trim references, colorway/size-scoped BOM overrides, labels and construction annotations with full asset/callout editability, costing columns, packaging/cutter fields, and accurate version-aware spreadsheets/PDF exports. Validate against at least one completed factory sample tech pack and the **official CLO-SET Excel sample** linked from [How To Excel Tech Pack](https://support.clo-set.com/hc/en-us/articles/45303206577817-How-To-Excel-Tech-Pack).

**Milestone 3: Collaborative factory web workspace.** Connect to existing ClothCraft team identities and share permissions; add review-only factory links, anchored comments, sample photo/measurement diffs, approved release snapshots and history. Follow the older local plan only after checking it against the current underlying API/security reality.
