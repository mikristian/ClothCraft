## Result for EXO implementation

**POM ownership is the next engineering question.** A production POM must store a stable ID and explicitly reference its source pattern(s) and an ordered length path in physical metres. The EXO UI must distinguish a measurement belonging to another pattern from an invalidated/removed POM: do not simply return an empty table or silently drop an attachment without a clear status. Support refresh/recompute controls or live recalculation with explicit semantics, and test across panel selection changes.

**Edge-split reference migration remains a higher-priority correctness requirement.** CLO's visible point split and seam/allowance display survive the interaction, while current EXO Rust `SplitBoundary` intentionally refuses sewn, notched or seam-allowance-linked segments. Atomic split must produce new stable left/right directed edge IDs; migrate sewing correspondences, notch fractions/arclength coordinates, allowances and POM path references by exact physical curve parameter; update symmetric counterparts; retain a reversible undo payload. Compare summed child arclengths to old edge length, and fail closed on an invalid remap.

**Dedicated next native controlled experiment:** In CLO create *one* new POM on a named panel, make the POM panel selection explicit, split the *same* measured boundary rather than the opposite torso, return to exactly the same named panel, and determine whether the POM row reappears and whether its measurement recomputes. A second control should select another pattern without editing geometry to determine whether the Object Browser filters POMs by current selection. Capture pattern Name Property Editor before/after and read actual POM length row each time. Follow with a notch on either side of a cutline split and compare selected notch Type, Angle, Length and location before/after.

## Integrity, concurrency and limits

At the last confirmed on-disk hash check, the original CLO sample and disposable fixture were both **912,850 bytes** and SHA-256 `eb24014f28e46cd513ea603a3c441ceeda9dc62bc301d6457848ffe906b87a83`. The user approved working with the disposable copy despite limited free space; no save to those files was intentionally performed. CLO may display its own autosave indicator, which is distinct from an explicitly requested authoritative fixture save. Do not infer autosave's destination or persisted contents from that indicator.

Other active work modified the same Swift inspector source during a later build. That attempted build reported `input file ... main.swift was modified during the build` and did **not** produce a verified new package for the separate boundary-vertex/POM experiment; that experiment is **not** marked passed. Avoid simultaneous builds to the shared signed inspector binary; coordinate one build/test process at a time or stage a distinct isolated QA helper with its own bundle identifier and TCC authorization.
