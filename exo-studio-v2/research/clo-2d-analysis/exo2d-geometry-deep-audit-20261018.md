# EXO 2D geometry, points, curves, references and measurements — code audit

Date: 2026-10-18. Read-only investigation of the current dirty repository, focusing on source behavior; no claim of full CLO parity. Production code was not changed. This investigation did **not** exercise the installed CLO application. The relevant official workflow evidence and CLO documentation links appear in `research/clo-2d-analysis/official-reference-findings.md` and `2d-window-workflow-refinement-20261018.md`.

## Architecture: two materially different 2D editors

1. `src/App.jsx:6529-6551` mounts `src/components/PatternEditor.jsx` for the project-local JS draft. `src/core/project.js:154-181` and `src/core/draftingPrecision.js:64-149` interpret coordinates in **centimeters**, with points `{x,y}` and optional **quadratic** control `{cx,cy}` keyed by mutable numeric edge index. The SVG uses `Q` curves (`PatternEditor.jsx:44-59`). Point and curve manipulation comes through callbacks in `App.jsx:2267-2327`; splitting, deletion, seam remaps and allowances come from `App.jsx:421-652,2406-2550`.
2. `src/components/ClothCraftWorkspace.jsx:1413,1430` mounts native `src/components/ClothCraftBoardV2.jsx` using an actual Rust template/mesh snapshot, authored through `edit({kind:...})`. Coordinates are **metres**. `research/oss/clothcraft/src/garment/polygon.rs:28-60` defines `PolygonPattern.points`, **stable named** `edges`, and **cubic** `curves: BTreeMap<String,[DVec2;2]>`. UI handle dragging goes through `src/core/vectorPatternBezier.js:23-47` and `ClothCraftBoardV2.jsx:779-845`, committing the entire `Shape` edit. Native split authoring lives in `research/oss/clothcraft/src/authoring.rs:866-945`; bridge command dispatch in `integrations/clothcraft/exo-session.rs:15-20`.
3. No single shared point/curve/topology command contract is evident in these call paths. Their different units, curve degrees, edge identities, and split restrictions require an explicit conversion specification before treating either workflow as interchangeable with the other.

## Prioritized findings and reproduction checks

### P0 — sewing-aware split unavailable in native editor

`research/oss/clothcraft/src/authoring.rs:866-896` rejects `SplitBoundary` if the edge participates in a seam, has a target length, or has even one notch/seam allowance. The UI nonetheless exposes the split tool and submits `SplitBoundary` at `ClothCraftBoardV2.jsx:920-937`. Contrast `App.jsx:421-652`, which splits a project edge, adjusts edge-index references, partitions seam intervals, remaps notches, and copies allowance values. Real construction often requires inserting a point after a seam has already been established; the native operation forces users to destroy construction metadata first. **Test:** create two native panels, sew named edges A/B, then `SplitBoundary` at half arc length of A; assert rejection and no revision/mesh change as current behavior, then design an acceptance test requiring two correctly directed sewing intervals with exact references, matching arc lengths, retained notches, and single-step undo. Repeat with target lengths and allowances. CLO reference: [Split Line](https://support.clo3d.com/hc/en-us/articles/115012380288-Split-Line), [Segment Sewing](https://support.clo3d.com/hc/en-us/articles/115012381248-Segment-Sewing).

### P0 — point deletion leaves secondary indexed construction references inconsistent in JS editor

`App.jsx:2481-2550` checks sewing and notches on the adjacent edges, then removes the vertex and adjusts curve indices, allowances, sewing endpoints, and notch indices. It **does not** iterate `piece.topstitches`, `piece.bindings`, `piece.zippers`, or other edge-index owners to shift their indices, nor does it reject deletion when those attachments touch the merged adjacent edges. In contrast, the split code *does* explicitly handle these collections at `App.jsx:500-511`. **Test:** create a ≥5-vertex piece with zipper/binding/topstitch on edge 3 or 4, delete vertex 1, and assert every surviving object still targets the geometrically same edge; separately attach a zipper to the merged previous/current edge and require a clear rejection or explicit migration. Verify array identity/metadata and undo.

### P1 — invalid sampled boundary can fabricate free-sewing geometry

`src/core/freeSewingGeometry.js:8-9` converts boundary indices into positions and `.filter(finitePoint)` removes invalid samples **without preserving gaps**. Its projection and range functions (`:23-89`) consequently connect the surviving vertices, potentially allowing selection/sewing across a nonexistent segment. This conflicts with `src/core/clothcraft2dGeometry.js:26-40`, which correctly splits incomplete boundaries into separate runs. **Verified minimal reproduction:** `node --input-type=module -e "import {cutlinePoints} from './src/core/freeSewingGeometry.js';console.log(cutlinePoints([0,1,2,3],[[0,0],[1,0],null,[5,0]]))"` prints `[[0,0],[1,0],[5,0]]`, i.e. creates an apparent link from x=1 to x=5. **Acceptance:** reject incomplete authoring boundaries, or project onto independent contiguous runs and never offer a selectable bridge; include missing vertex at middle/ends, degenerate curves, and reverse orientation.

### P1 — curve/point mode and native handle controls are materially different from React

`ClothCraftBoardV2.jsx:1418-1423` makes native vertex clicks in Curve mode invoke `CurvePoint` toggle (or Alt straightening) rather than initiate anchor movement; Point mode invokes drag `Anchor` at `:827-845`. Native selected edges expose two cubic controls at `:1425-1443`, and `vectorPatternBezier.js:19-47` mirrors adjacent tangent length/direction unless Alt breaks tangency, Shift angle snaps. React editor exposes one quadratic midpoint/control (`PatternEditor.jsx:1346-1365`) and applies numeric along/depth or XY edits (`:1460-1479`). **Test:** edit an armscye and neckline at seams/shoulders in both screens, inspect stable geometry and actual handle count, test Alt/Shift, smooth-vs-corner continuity, mouse/keyboard control, selected edge properties, save/reopen. **Requirement:** define visible mapping between endpoint/corner/smooth anchor editing and native cubic controls; include curve joins on vertex drag and numeric coordinates. CLO docs: [Edit Bézier Curves](https://support.clo3d.com/hc/en-us/articles/115002753388-How-to-Edit-B%C3%A9zier-Curves), [Edit Pattern](https://support.clo3d.com/hc/en-us/articles/115012380108-Edit-Pattern).

### P1 — 2D POM is partly a visual tape, not a persistent bound measurement model

Native overlay `ClothCraftBoardV2.jsx:298-319` displays rotated/world-axis bounding extents for panels; `:1499-1508` measures a two-point **ephemeral tape** on SVG. `src/core/clothcraftSelectionMetrics.js:49-103` computes current native edge/perimeter and seam interval lengths from Rust UV/3D sampled boundaries, and `ClothCraftWorkspace.jsx:1401` displays seam mismatch. These are valuable readouts but not the complete CLO Create/Edit POM data model: named multi-segment point-of-measure stations, bound outline/internal-line references, grouped graded measurements, editable start/end anchors. The separate JS project `src/core/measurements.js:43-86` adds hard-coded fractional-height apparel stations; `:45-62` assumes piece IDs `front` and `sleeve-left`, and armhole as edges 1+2. **Test:** create a custom garment with different edge ordering and an internal armhole curve; verify projected chest/armhole readings against actual chosen geometry, then move/grade the pattern and compare bound stations before/after. Native tape should persist to model/reopen if the UX calls it a POM. CLO: [Create POM](https://support.clo3d.com/hc/en-us/articles/360025716774-Create-POM), [Edit 2D POM](https://support.clo3d.com/hc/en-us/articles/360025716814-Edit-2D-POM).

### P1 — native deletion constraints protect data but prevent mature contour editing

`research/oss/clothcraft/src/authoring.rs:958-1005` rejects point deletion if either neighbor edge belongs to a seam, has target lengths/notches/allowances or has any cubic handles. This avoids orphan records but is disruptive for production drafting. React deletion conversely silently drops adjacent curve controls (`App.jsx:2512-2523`) and merges allowances by maximum (`:2507-2536`), which can visibly straighten curved necklines/armholes. **Test:** remove a smooth Bézier shoulder/neck anchor and calculate Hausdorff distance of pre/post contour; require an explicit merge strategy (fit cubic subject to tolerance or preview destructive simplification) with appropriate construction remaps. Deleting a clicked point should have predictable undo/redo and show metadata blockers precisely.

### P2 — certain split and measurement approximations deserve targeted regression coverage

`PatternEditor.jsx:740-759` maps pointer onto a 24-step sampled quadratic and passes an approximate **parameter** to `splitPieceEdgeInProject`; numeric `App.jsx:2415-2436` instead converts desired arc fractions using `splitParameterAtArcFraction` (`src/core/draftingSplit.js:45-55`). The approximation makes click-derived split placement zoom/curvature sensitive compared with measured arc fractions. `App.jsx:464` then projects the new anchor back onto the old edge with 64 samples to remap notch/sewing fractions; if the curve is extremely bowed, this can introduce small errors. **Test:** highly curved 60 cm quadratic with an off-center control; compare click split location and precision 50% split against an adaptive arc-length integrator, and confirm conservation of curve contour, lengths, seam fractions and notch positions to 0.01 mm. `src/core/draftingTopology.js:54-135` tests outline self-intersections with 8 or 24 chord samples in `App.jsx:2267-2327`, so adversarial near-tangent loops merit higher-resolution validation before manufacturing export.

### P2 — native split length follows tessellated rather than exact cubic arclength

`research/oss/clothcraft/src/authoring.rs:468-486` finds split parameter by repeatedly evaluating `curves::flatten(... FLATNESS_M)` sampled length. de Casteljau split (`:457-466,920-940`) **does** preserve the cubic contour exactly, but the physical split station is limited by mesh-flattening tolerance. **Test:** cubic with sharp S shape and 50% `at_m`; compare native parameter against high-accuracy Gaussian/adaptive integration while checking that before and after edge total length stays equal within requested production tolerance.

### P2 — polyline invalid-point filtering has downstream diagnostic implications

Native panel-span algorithms `src/core/clothcraft2dGeometry.js:103-140` pair crossings using even-odd intersection rule across `Object.values(boundaries)`. They work for expected complete outer rings, but no explicit complete/closed contour invariant is imposed at this layer. **Test:** missing endpoint, duplicated/reversed shared edge, disjoint islands, and hole boundaries; assert physical spans agree with a canonical cut contour and never infer a valid 2D POM across a boundary gap. Preserve the `boundarySegments` gap guard.

## Existing strengths to preserve

- Native geometry names edges (`polygon.rs:31-38`) and uses physically meaningful metres; `SplitBoundary` performs exact de Casteljau contour partition (`authoring.rs:920-940`).
- Native per-edge 2D/3D and partial seam lengths derive from compiled boundary UV and live vertices (`clothcraftSelectionMetrics.js:7-103`), which correctly decouples screen zoom from measurements.
- React quadratic lengths use Rust or adaptive Simpson (`draftingPrecision.js:98-127`), while `edgePointAt` maps arc-length fractions (`project.js:176-185`). Numeric split has sensible finite/range input validation (`draftingSplit.js:13-55`).
- React `isDraftEditValid` blocks self-crossing point/curve changes (`draftingTopology.js:54-135`), and edit callbacks use undoable mutations (`App.jsx:2280-2327`). Native cubic handle edits are actual model `Shape` mutations, not merely SVG adornments (`ClothCraftBoardV2.jsx:827-845`).

## Recommended implementation order for prime

1. Add native topological split/remap transaction covering stable edge names, paired sewing intervals, allowlisted edge metadata and notches; preserve naming/undo, with Rust unit + installed 2D browser QA. Reject ambiguous remaps explicitly.
2. Fix indexed-edge attachment migration when deleting JS anchors and fix `freeSewingGeometry` invalid gap bridging; add compact pure Node tests proving identity and safe fail-closed geometry.
3. Specify a common pattern-topology and units boundary for native cubics and JS quadratics, and implement a full anchor/segment/handle editing interaction compatible with actual CLO observed behaviors.
4. Add first-class persistent, bound POM paths (including curved/internal-line stations and grade sizes), then audit heuristic readouts and build cross-editor visual+numeric regression fixtures.
5. Exercise native CLO interactively with inspector and reference screenshot/recording of each point/curve/segment workflow before claiming parity; documentation above is a functional reference, not proof of identical UI.
