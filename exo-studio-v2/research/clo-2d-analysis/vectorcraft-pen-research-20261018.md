## Confirmed implementation (source links pinned to SHA)

1. **Pen** — [`crates/tools/src/pen.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/crates/tools/src/pen.rs). `PenTool` tracks the active path, last placed anchor, drag state, pending incoming handle, snapping and endpoint joining. Click places a corner; click/drag creates symmetric smooth handles beyond a 3-screen-pixel drag threshold. Alt can break handle symmetry and convert/edit anchors and segments; Shift constrains direction to 45-degree increments; Space translates the dragged anchor and handles. Clicking first anchor closes; existing open endpoints can be continued/joined; Enter/Esc terminates. These interactions emit engine command actions with preview/commit semantics.
2. **Anchor model and cubic evaluation** — [`crates/geom/src/path.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/crates/geom/src/path.rs). `Anchor { p, h_in, h_out, kind }` stores three absolute points per anchor with `Corner` or `Smooth` behavior; absent handles equal `p`. `SubPath { anchors, closed }`, and `PathData { subpaths }` retain open/closed contour identity. Consecutive anchors A/B define cubic `CubicBez::new(A.p, A.h_out, B.h_in, B.p)`; `set_handle` keeps smooth anchors collinear while preserving the opposite handle's length, unless `independent` breaks coupling. Includes insert/split, segment bend, reversion, SVG `BezPath` conversion, nearest-point hit testing and arc length through `kurbo`.
3. **Anchor Point editing** — [`crates/tools/src/draw2/anchor.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/crates/tools/src/draw2/anchor.rs). Click a smooth anchor to convert to corner; drag an anchor to pull handles; click a handle to retract that side; drag a handle independently; drag a segment to reshape. Handle and anchor picking take precedence over segments, subject to visible-handle settings and tolerance. Includes snapping and Shift constraints.
4. **Pencil drawing** — [`crates/tools/src/draw2/gesture.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/crates/tools/src/draw2/gesture.rs). `GestureTool::new("pencil")` collects pointer samples, snaps stroke endpoints, previews `path.freehand` live and commits at release. Default fidelity is **1.5** (document units/points per code); continuation of selected open paths and close/merge behavior exist. Pencil emits position samples; Paintbrush adds per-sample pressure when less than 1.0. Live fitted-path generation is behind a command, rather than being stored as uneditable samples.
5. **Curve fitting** — [`crates/tools/src/draw2.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/crates/tools/src/draw2.rs) contains the `catmull_rom` fitting and `curvature_spline`/`smooth_handles` helpers used by drawing/editing. Curve smoothing is not equivalent to textile fit validation. Engine `path.freehand` command behavior should be inspected in full before porting it; this snapshot is focused source research, not integration QA.
6. **Web stylus input is distinct from Pencil** — [`apps/vectorcraft-web/src/pencil.rs`](https://github.com/storytold/vectorcraft/blob/73f40e3fd3fd6957508f18af1bf3bff93a9eb3e7/apps/vectorcraft-web/src/pencil.rs) handles browser stylus/touch/pointer events and coalesced samples; it is a pointer-input adapter, not the freehand geometry tool.

## Mapping to EXO's real existing data model

- Existing EXO UI contour in `src/components/PatternEditor.jsx`: `piece.points` is a vertex array; `piece.curves[edgeIndex]` is a **quadratic** single-control `{cx, cy}` for the edge, rendered with SVG `Q`. See `src/core/project.js` `sampleEdge`, `edgeLength` and `edgePointAt` and `src/core/draftingPrecision.js`. The Rust geometry kernel `rust/exo_geometry_kernel/src/lib.rs` currently computes quadratic Bézier length, including a native C ABI. `src/core/garmentCode.js` serializes curved edges as a single relative control point for garment export; seams identify edge indices. A direct wholesale switch to cubic curves would break length, sewing and persistence code.
- **Safe first integration**: place a VectorCraft-inspired interaction/controller behind EXO's existing pattern-edit tool; handle pointer down/move/up, canvas-to-centimeter transform, snapping, preview versus commit, selection and undo. For existing quadratic curves, expose the single quadratic handle and corner/smooth behavior with EXO's current persistent format intact. Pencil can fit a polyline then simplify/smooth to supported quadratic spans; preserve source samples transiently for interactive editing.
- **Full cubic option**: introduce a versioned, typed curve representation (quadratic or cubic) in EXO's domain model, with two absolute controls for cubic edges and explicit corner/smooth handle constraints. Upgrade *all* geometry consumers together: renderer, hit tests, length/nearest-point/offset/seam allowances, split/merge/reverse, contour orientation, sewing edge IDs, grading, serialization, Rust geometry kernel and GarmentCode/exports. Preserve stable edge identity or remap seam/notch references on insertion/deletion.
- An exact quadratic segment `P0,Q,P1` maps losslessly to cubic controls `C1=P0+(2/3)(Q-P0)` and `C2=P1+(2/3)(Q-P1)`. Cubic-to-quadratic is **not** generally exact. To export to the present EXO quadratic format, approximate with measured, tolerance-bounded subdivisions or retain original cubics in an extension field; reject any conversion that would silently alter cut/sew length or notches.
- Pen/Pencil should be available through EXO's tool index and usable inside its existing Edit Pattern workflow; do not duplicate toolbars. Keep pattern coordinates in physical units and make screen-space snap radius scale with zoom. Show anchor handles and continuity on neckline and armscye; changing a control must recalculate edge lengths/seam allowance and preserve grading/sewing references.
