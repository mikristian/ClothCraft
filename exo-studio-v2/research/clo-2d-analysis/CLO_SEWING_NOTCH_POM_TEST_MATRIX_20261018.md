## Behavior contracts for EXO ClothCraft

1. **Seam-connected topological split:** when an edge is split into two named edges, preserve a directed one-to-one or one-to-many physical interval mapping for every sewing constraint referencing that edge. Verify cumulative physical lengths, endpoint continuity, notch fractions, seam allowance values, grading correspondence, 3D cloth sync and undo/redo atomically. The existing Rust `SplitBoundary` in `research/oss/clothcraft/src/authoring.rs` conservatively refuses sewn/allowanced/notched edges; this is currently safer than silent reference loss. The live CLO side-line split demonstrates the *visible geometry* standard but does not yet establish its underlying ID migration algorithm.
2. **Named notch geometry:** `research/oss/clothcraft/src/garment/polygon.rs` already has an edge-keyed `notches: BTreeMap<String, Vec<EdgeNotch>>`. Extend authoring/UI metadata to support CLO-observed notch name, type I and future types, perpendicular/custom angle, numeric length/depth, flip, lock, symmetrically linked property updates and independent Undo/Redo. Ensure a notch is tied to a stable physical fraction or arclength on an authoritative named edge rather than stored as arbitrary SVG decoration.
3. **Separate seam allowance shape:** the Rust polygon also stores edge-keyed `seam_allowances: BTreeMap<String,f64>`. Its authoring UI needs a physically offset **cutting path** visualization, per-edge width/property editing and corner joins, and correct behavior under topological split. The mode-only test is insufficient to dictate CLO's exact corner algorithm. Add generated offset self-intersection and fold checks and export tests.
4. **First-class POM authoring:** EXO's native board currently provides a temporary `tape` overlay, and `src/core/clo7NativeToolCapabilities.js` correctly marks native 2D POM tools as temporary measurement inspection. CLO's live browser creates a **document POM table row** with stable row numbering, editable description and physical length in centimetres. EXO should implement first-class typed `POM { id, label, path, unit, length, grading, revision }` records with stable references to outline edges/internal lines; support trace gesture, explicit completion, selection, rename, recompute on geometry edits, save/reopen and defined Undo/Redo transactions. Existing tech-pack `pom` tables are spec data; do not mistake them for geometrically linked CAD POM entities.
5. **2D and 3D lengths:** the native POM selection in CLO's Property Editor showed **Total 3D Length 26.18 cm** and **Selected 3D Length 26.18 cm** in this particular state, while the POM browser showed **Length(cm) 26.18**. These are distinct UI properties, not proof that 2D and 3D measurements are always identical. Keep separate numeric sources and stale/revision flags in EXO.
6. **Intended test isolation:** all helpers require the copied document title before posting authoring gestures. Avoid reopening the garment below CLO's previously observed ~10 GiB warning threshold, and distinguish a native menu returning success from the desired authoring state appearing on screen. After testing, leave the editor in neutral `Transform Pattern` mode and retain before/after evidence.
