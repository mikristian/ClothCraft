# Immutable CPU and Metal parity validation

`node --test scripts/engineering/physics-lab-20261018/validate-parity.test.mjs` passes six fixture contract tests. `validate-parity.mjs` independently accepts the existing 40-step CPU and GPU snapshots as comparable (`ok: true`), even though their numerical outcomes fail parity. It checks SHA256 executable and avatar identity, initial mesh counts, seam and time identity, 40 complete ordered steps, equal timestep/iterations, valid step wall times, consistent trajectories, and session-open reported CPU/GPU selection. Different *live source* fingerprints are allowed when executable bytes match.

The historical comparison records CPU reaching max seam gap 25 mm at step 13 (7,089.688415 ms accumulated native step wall time), 10 mm at step 16 (8,513.016914 ms), and 5 mm at step 27 (13,826.517289 ms). GPU reached none in 40 steps. There is consequently no evidenced equivalent-geometry acceleration; native `step_ms` excludes process startup. At step 40 the baseline CPU seam gap is 4.041 mm versus GPU 326.845 mm.

Backend identity comes from a **session-open** string, not instrumented per-step execution. Existing fixture JSON does not attest to per-step Metal dispatch, native fallback, GPU kernel timing, or readback timing. A fallback occurring *after* open would be undetectable here. An inaccurate backend string would likewise be unverified. The validator rejects a reported CPU initial backend on a requested GPU fixture and documents this remaining observability limit.

## Hybrid fallback contract

The isolated experimental adapter (`.exo-build-scratch/physics-gpu-refresh-20261018T204719Z/src/bin/exo-session.rs`, read-only inspection) emits `actualStepBackend` = `GPU`, `CPU fallback`, or `CPU`, and cumulative integer `gpuCpuFallbackCount` on the session snapshot. The fixture runner copies these values into each step's trajectory and timeTrajectory; the validator accepts `GPU` and explicit `CPU fallback` for a GPU-requested session. `CPU` is valid on a CPU-requested session but **invalid without the fallback label** on the GPU run. Counters must start from zero on the first experimental step, advance exactly once for each fallback step, and never decrease or jump. Complete telemetry must be present on every step once any GPU step includes it. If both trajectory and snapshot carry telemetry, they must match.

The validator classifies an accepted GPU-requested run with fallback as `hybrid_gpu_cpu_fallback`, preserving physical comparison eligibility while explicitly returning `gpuAccelerationClaimAllowed: false`. An entirely GPU-reported trace becomes `gpu_reported_all_steps`; legacy traces are `gpu_backend_unattested_per_step`. Neither latter classification independently certifies GPU acceleration or physical equivalence. The optional per-step telemetry is a native assertion, not hardware dispatch proof. Nine synthetic regression tests pass, including explicit fallback, all-GPU, missing/unknown enum, skipped/decreasing counter, and legacy fixture validation.

## Independent CPU repeatability check

Three sequential, independently launched native CPU fixtures used the exact immutable `physics-immutable-20261018/exo-session` executable (SHA256 `b3c2258e590d3bb794787f6e754e640c2f83db5cf6acfeb1de813c8057d137eb`) with `EXO_PHYSICS_STEPS=12` and `RAYON_NUM_THREADS=2` (hard-coded by `run.mjs`). Run reports: `/tmp/exo-worker2-cpu-repeat-{1,2,3}.json`. All three recorded bitwise identical 12-step `tshirt` max seam gaps, exactly matching the first 12 steps of `immutable-cpu-arm64-40step.json`; final step-12 gap 37.54394661388312 mm. Each fixture's internal CPU repeatability flag also passed. Live source fingerprint was `3a6537f64f6b8c284df4f0c80906731fe35983120a9b72cfe4cdf19063ffc438` on all three runs but does not identify the executable's build provenance.

**Crucial comparison caveat:** the divergent experimental scratch `fallback-benchmark.json` identifies executable SHA256 `8c544f4ad5d6f56bad91ce274e3f97a9978ff2b4b2b8c040357bee0971ebdcdf`, which **differs from** the immutable baseline SHA. Thus the cross-run CPU discrepancy cannot yet establish Rayon nondeterminism or an equal-binary regression. The 12-step repeatability experiment supports deterministic behavior for the baseline binary under the tested conditions; it does not guarantee 40-step determinism or characterize the separate scratch executable.

Read-only solver inspection: `src/gpu_vbd.rs` has an optional `check_gradients` probe (around lines 305–375), comparing GPU energy and force against CPU autodifferentiation at the same rounded f32 coordinates; it does **not** compare the 3×3 Hessian or line-search decisions. `src/vbd.rs` refreshes contact geometry during iterations when candidate truncation reaches a threshold (around lines 358–395); the production GPU path batches all iterations after one contact build (around lines 390–405). Thus neither a gradient mismatch at step 4 nor a Hessian determinant defect has been experimentally established.
