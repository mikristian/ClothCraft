# EXO Physical Validation Lab (2026-10-18)

Run from the repository root: `node scripts/engineering/physics-lab-20261018/run.mjs`.

The harness launches the existing Rust `exo-session` native executable separately for T-shirt, dress, and a repeated T-shirt control; requests `open`, then fixed-count single `step` calls. Default is 3 steps per case. Override `EXO_PHYSICS_BINARY`, `EXO_PHYSICS_AVATAR`, `EXO_PHYSICS_OUTPUT`, `EXO_PHYSICS_STEPS` to select an already built binary, avatar and output. CPU is selected by omission of `--gpu`. Each case gets a fresh process. Inputs are SHA-256 fingerprinted and no production app or solver source is modified.

Opt-in GPU smoke: `EXO_PHYSICS_GPU=1 EXO_PHYSICS_STEPS=1 EXO_PHYSICS_BINARY=/path/to/feature-enabled/exo-session node scripts/engineering/physics-lab-20261018/run.mjs`. GPU mode passes `--gpu`, runs one T-shirt case and writes `docs/physics-lab/smoke-gpu.json` by default. CPU remains the default. Reports include requested backend, native backend claim, executable SHA-256 and current source SHA-256; source fingerprint alone does not establish provenance of a prebuilt executable. GPU and CPU runtime measurements are not compared unless identical source build, fixture, solver settings, and corresponding executable identity are established.

This short run measures **initial assembly transients**, not a converged garment fit. Both presets begin with substantially separated panels. Three steps cannot establish equilibrium or demonstrate a seam solver defect, fit failure, or release failure. The native snapshot's `seams[].gap_m` provides the **initial, pre-step maximum seam gap**, also sampled after each step with simulation time in `timeTrajectory`. The VBD `snapshot.metrics` field supplies all step metrics; the baseline includes the reported backend, vertex/triangle/seam counts and full short step trace. Thresholds (25 mm maximum seam gap, 15% p95 extension, 60% maximum extension, 0 m minimum distance) are *provisional screening references intended for later settled-state characterization*. Transient exceedances are diagnostic observations only; no release gate is applied. A missing/nonfinite metric is inconclusive. `minimum_distance_m` is an engine proximity metric rather than independently verified cloth/body penetration; penetration remains inconclusive regardless of its reported value.

The repeated T-shirt detects gross nondeterminism by comparing selected physical values and contact counts per step exactly, excluding wall-clock timing measurements. The optional GPU run is a single **smoke test**, not a comparable performance or physical-parity benchmark. CPU and GPU comparisons require separately identified same-source binaries and adapter metadata. The report never asserts independently verified GPU acceleration or contact correctness based on a backend label alone. If a native session fails, the case remains inconclusive with its error. Baselines depend on binary and avatar hashes and cannot be compared across code changes without reviewing those identities.

### Same-binary CPU/Metal comparison

The safer one-command parity gate is `EXO_PHYSICS_BINARY=/absolute/path/to/feature-enabled/exo-session EXO_PHYSICS_STEPS=3 node scripts/engineering/physics-lab-20261018/run-parity-immutable.mjs`. It first copies the executable into a unique scratch directory, records the SHA-256, runs CPU then GPU from **that unchanged copy**, writes `cpu.json`, `gpu.json`, `comparison.json` and `manifest.json`, and exits nonzero on a physical-parity failure. Set `EXO_PHYSICS_PARITY_STRICT=0` only to collect reports without blocking a research job. This does not publish or modify the installed app.

On an arm64 macOS machine with a working Metal adapter, first build from the current source: `CARGO_INCREMENTAL=0 ~/.cargo/bin/cargo build --manifest-path research/oss/clothcraft/Cargo.toml --locked --offline --features desktop --bin exo-session`. Then run `EXO_PHYSICS_STEPS=3 EXO_PHYSICS_OUTPUT=docs/physics-lab/same-source-cpu-arm64.json node scripts/engineering/physics-lab-20261018/run.mjs` and `EXO_PHYSICS_GPU=1 EXO_PHYSICS_STEPS=3 EXO_PHYSICS_OUTPUT=docs/physics-lab/same-source-gpu-arm64.json node scripts/engineering/physics-lab-20261018/run.mjs`, followed by `node scripts/engineering/physics-lab-20261018/compare-cpu-gpu.mjs`.

The comparison requires matching executable SHA256, avatar SHA256, mesh sizes, initial seam separation and time/iteration settings; it also records the current source fingerprint for provenance review. It reports per-step geometry differences and observed wall times. Provisional parity screens are **5 mm seam difference** and **5 percentage points p95 extension difference**; these are numerical diagnostic screens, not calibrated fit or release approval. A CPU/GPU speed-up claim is **blocked** whenever their physical trajectories differ materially. The short default session measures early assembly, not equilibrium, settled textile fit or verified penetration.

Reports now also provide time to comparable *assembly milestones* (maximum seam gap <=25, <=10 and <=5 mm), including physical simulation time and accumulated wall-clock processing time. An unreached milestone stays `null`; no equivalent-geometry speed comparison is derived until both backends actually achieve that same condition. In the recorded baseline 40-step replay, CPU reached 10 mm by step 16, while GPU had not reached 25 mm by step 40. These milestone limits only measure sewing-assembly progress, not collision-safe garment fitting.

Note: the actual executable SHA-256 is the comparison's required source-of-truth. The report also records the current adapter source fingerprint, but a mismatch in that *mutable* fingerprint is informational if both experiments used byte-identical immutable executable binaries. Each step additionally records maximum and RMS vertex speed from actual mesh displacement divided by the accepted physical timestep. These speeds help diagnose whether the cloth is still moving but cannot alone prove contact-correct equilibrium.

To enforce the preliminary parity screen in automated QA, use `EXO_PHYSICS_PARITY_STRICT=1 node scripts/engineering/physics-lab-20261018/compare-cpu-gpu.mjs`; it returns nonzero when trajectories differ beyond these limits. Run without strict mode to generate a diagnostic report without failing the script. Both variants always retain `userFitCertified:false`.

To prevent concurrent Rust builds from replacing the tested binary mid-experiment, copy the compiled `exo-session` into a unique read-only benchmark scratch path first and set `EXO_PHYSICS_BINARY` to that same absolute path for both CPU and GPU runs. One such pair of 40-step CPU/Metal reports is saved as `immutable-cpu-arm64-40step.json` and `immutable-gpu-arm64-40step.json`, with machine-readable comparison `immutable-40step-comparison.json` and executable SHA-256 `b3c2258e590d3bb794787f6e754e640c2f83db5cf6acfeb1de813c8057d137eb`. These runs remain transient physical trajectories, not accepted garment fit.
